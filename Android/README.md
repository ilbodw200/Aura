# AURA VPN для Android

Android 8.0+, Kotlin/Jetpack Compose, настоящее ядро sing-box 1.11.15. APK содержит arm64-v8a, armeabi-v7a и x86_64.

## Архитектура

- `AuraActivity` — Compose и системное разрешение VPN, управление жизненным циклом UI.
- `AuraScreens` — три вкладки, серверная панель, поиск, измерения и настройки.
- `AuraViewModel` / `AuraRepository` — StateFlow, Coroutines, атомарные изменения конфигураций и DataStore оформления.
- `Vault` — AES-256-GCM с ключом Android Keystore. Данные подписок совместимы с существующим хранилищем.
- `AuraVpnService` — последовательная очередь запуска/остановки, foreground-уведомление, монитор основной сети, повтор при ошибках с ограниченной задержкой.
- `CommandServer` / `CommandClient` — счётчики реального трафика sing-box через приватный UNIX-сокет. Отсутствие счётчиков не заменяется сгенерированными числами.
- `TunnelHttp` — проверка публичного IP через loopback SOCKS-вход текущего ядра с отдельным случайным паролем на сессию. HTTPS проверяет имя и сертификат; прямого fallback нет.
- `MainActivity` — внутренние проверенные редакторы импорта, QR, подписок, правил, приложений и копий. Старого главного экрана в навигации нет.

## Настройки и поведение

Запуск при открытии приложения использует обычное системное согласие VPN. Автопереподключение восстанавливает интерфейс после возвращения сети и повторяет ошибки запуска ядра до пяти раз с задержкой 4–60 секунд. Отзыв разрешения и ручное отключение отменяют повтор.

Always-on и Kill Switch настраиваются в системных параметрах Android: приложение открывает их и объявляет поддержку Always-on. Блокировка трафика без VPN выполняется Android Lockdown, а не декоративным переключателем.

DoH направляется через маршрут VPN. При включённой блокировке IPv6 трафик IPv6 захватывается TUN и отклоняется правилом ядра. В Split Tunneling можно выбрать только приложения VPN или приложения обхода. Явные direct-правила и исключённые приложения намеренно обходят VPN.

MTU: 1280–9000, по умолчанию 1400. Сетевые настройки меняются при выключенном VPN и применяются к следующей сессии. Протокол задаётся реальной конфигурацией сервера; кнопка протокола открывает подходящие существующие серверы.

Автовыбор сначала измеряет выбранный список по настройкам GET/HEAD/TCP/ICMP, затем выбирает минимальный успешный результат. Проверки отменяются после текущего нативного запроса. TCP/ICMP не подтверждают прохождение HTTP через прокси.

## Сборка

Требуются JDK 17, Android SDK 35, NDK 28.0.13004108 и Go 1.24.2. В Linux/macOS из корня:

```sh
bash Scripts/bootstrap-android-core.sh
Android/gradlew -p Android testReleaseUnitTest assembleDebug
```

Для release задаются `AURA_SIGNING_STORE` (PKCS12, alias `aura`) и `AURA_SIGNING_PASSWORD`. Ключ хранится в GitHub Actions Secrets. Публичная версия — 1.0; Android versionCode увеличен до 8, чтобы обновление сохранило установленные данные.

[Workflow сборки](https://github.com/ilbodw200/Aura/actions/workflows/android.yml) проверяет JVM-логику, Compose, VPN-службу на эмуляторе, подпись и запуск release APK. Сценарий службы использует настоящий Android TUN и локальный тестовый SOCKS-сервер. Тестовые серверы не включаются в release APK.

## Границы проверки

Физический телефон, сеть оператора, сервер провайдера и DNS/IP leak-тест через этот сервер требуют отдельной проверки. Достижение 60 FPS на всех устройствах не заявляется; эффекты отключаются в настройках и учитывают системное отключение анимаций.

WireGuard-конфигурации, XHTTP и фирменные зашифрованные ссылки Happ не поддерживаются текущим импортом. Приложение не выдаёт VPN-подписки и не содержит демонстрационных серверов.
